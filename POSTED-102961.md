Adding a provider-side data point, since this issue decides whether a class of plugin can
exist.

I maintain [CTRLRun](https://github.com/CTRLRun/ctrlrun), an execution safety layer for agent
actions, and I have been building a `before_tool_call` provider on top of it. Its whole model
turns on a distinction this payload cannot currently express: the difference between **the
call did not execute** and **we cannot tell whether it executed**. Those are separate states
with separate consequences. A call that definitively did not run can be retried. A call whose
outcome is unknown must not be, until a human says which it was, because retrying it is how a
committed effect happens twice.

At `after_tool_call` today, for exec and bash-family tools, both of those arrive identically:
no `event.error`, and `event.result` as bare text. So a provider has three choices and all of
them are bad. Treat the absence of `error` as success, and a failed call is recorded as a good
one. Parse stdout/stderr, and the policy layer's correctness now depends on text formatting.
Treat everything unreadable as unknown, and every successful exec parks an effect for a human
to resolve, which makes the gate useless in practice.

**Option 2 in @jgrandguillaume's framing is enough**, and it is the one I would ask for:
`details.exitCode` and `details.status`, or a boolean `isError`, alongside the existing string.
A provider does not need the full `ToolResult` shape to make this decision, and option 2 does
not commit the project to passing structured results through every native relay. Option 1 is
strictly better if it is cheap, but it should not block option 2 from landing.

One property matters more than which option wins: whatever is added should make **absent**
distinguishable from **succeeded**. If a new field is simply missing when the host does not
know, a careful plugin can fail closed on it. If the host reports a default that reads as
success when it has no information, no plugin can recover from that, and every provider built
on this hook inherits the ambiguity permanently.

Happy to test a candidate shape against a real provider and report back if that is useful.
